Projeto 5 · Avançado

API REST de tarefas, segura e containerizada Secure, containerized REST API

Uma API de back-end completa: CRUD, validação, testes, CI, autenticação, auditoria OWASP, Docker e PostgreSQL.

Requisitos

  • CRUD de tarefas com códigos de status corretos (201, 204, 400, 404, 409).
  • Validação de entrada com mensagens de erro consistentes (JSON).
  • Documentação OpenAPI gerada ou escrita.
  • Testes de unidade e de integração; CI no GitHub Actions.
  • Cadastro e login com hash de senha (Argon2id/bcrypt) e cookie HttpOnly; Secure; SameSite.
  • Cada usuário só vê as próprias tarefas (sem BOLA).
  • Dockerfile multi-stage (usuário não-root) e compose.yaml com PostgreSQL.

Etapas

Critérios de aceite

Seu projeto está pronto quando tudo isto for verdade (e, idealmente, verificado por testes):

  • Teste automatizado prova que o usuário A recebe 404 ao acessar a tarefa do usuário B.
  • Tentativas de SQL injection nos campos não alteram o banco (teste).
  • docker compose up sobe API e banco do zero.
  • Nenhum segredo no repositório (variáveis de ambiente).

Para ir além

  • Paginação com cursor.
  • Logs estruturados e endpoint /health.
  • Deploy em um provedor de nuvem com HTTPS.

Pré-requisitos e habilidades

Módulos: HTTP, REST e APIs

  • HTTP e APIs REST
  • Estratégia de testes e CI
  • Fundamentos de segurança
  • Segurança web
  • Containers

Inglês do projeto

  • ponto de extremidade→endpoint

    Uma rota da API: método + caminho.

  • limitação de taxa→rate limiting

    Restringir quantas requisições um cliente pode fazer em um período.

  • autorização quebrada em nível de objeto→broken object level authorization (BOLA)

    Falha em verificar se o usuário pode acessar aquele registro específico.

Como entregar

Crie um repositório público no GitHub para o projeto, com README (o que é, como rodar, como testar, decisões), commits pequenos e frequentes e, a partir do Projeto 2, testes automatizados. Veja o guia de carreira para transformar o projeto em vitrine.
