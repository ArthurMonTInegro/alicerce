Projeto 9 · Projeto final

Aplicação full-stack em produção Full-stack application in production

Front-end, API, banco e deploy com CI/CD e observabilidade, resolvendo um problema real de alguém que você conhece.

Requisitos

  • Um usuário real (familiar, ONG, comércio local) com um problema concreto e escrito.
  • Front-end acessível, API autenticada e banco relacional com migrações.
  • CI/CD: testes, build e deploy automáticos a cada merge na main.
  • Logs, métricas mínimas e alerta de indisponibilidade.
  • Documento de decisões de arquitetura (ADRs) com pelo menos 3 decisões.

Etapas

Critérios de aceite

Seu projeto está pronto quando tudo isto for verdade (e, idealmente, verificado por testes):

  • O usuário real usou a aplicação e deu feedback documentado.
  • Rollback de um deploy ruim em menos de 5 minutos, testado.
  • README permite que outra pessoa rode tudo localmente com 3 comandos.

Para ir além

  • Testes end-to-end com Playwright.
  • Orçamento de desempenho na CI.

Pré-requisitos e habilidades

Módulos: HTTP, REST e APIs, Normalização, índices e transações, Testes e CI/CD, Containers e Docker

  • Back-end e autenticação
  • JavaScript e DOM
  • Modelagem, índices e transações
  • Estratégia de testes e CI
  • Deploy e observabilidade
  • Segurança web

Inglês do projeto

  • produto mínimo viável→minimum viable product (MVP)

    A menor versão que já entrega valor real.

  • registro de decisão de arquitetura→architecture decision record (ADR)

    Documento curto: contexto, decisão, consequências.

  • observabilidade→observability

    Capacidade de entender o sistema por logs, métricas e traces.

Como entregar

Crie um repositório público no GitHub para o projeto, com README (o que é, como rodar, como testar, decisões), commits pequenos e frequentes e, a partir do Projeto 2, testes automatizados. Veja o guia de carreira para transformar o projeto em vitrine.
