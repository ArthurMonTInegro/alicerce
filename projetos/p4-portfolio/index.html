Projeto 4 · Intermediário

Portfólio pessoal acessível Accessible personal portfolio

Seu site pessoal em HTML, CSS e JavaScript puros, acessível, responsivo, publicado, e o seu GitHub organizado como vitrine.

Requisitos

  • HTML semântico (header, main, nav, section, footer) com hierarquia de títulos correta.
  • Layout responsivo com Grid/Flexbox, sem framework.
  • Tema claro/escuro lembrado com localStorage e respeitando prefers-color-scheme.
  • Filtro de projetos por tecnologia e formulário com validação acessível.
  • Publicado (GitHub Pages ou similar) com domínio HTTPS.
  • Cada projeto da trilha em um repositório com README, licença e .gitignore.

Etapas

Critérios de aceite

Seu projeto está pronto quando tudo isto for verdade (e, idealmente, verificado por testes):

  • Navegável 100% por teclado, com foco sempre visível.
  • Lighthouse: Acessibilidade 100, Desempenho ≥ 90.
  • Sem erros no validador do W3C.
  • Funciona em tela de 320 px sem rolagem horizontal.

Para ir além

  • Página de cada projeto com estudo de caso (problema, decisões, resultado).
  • Versão em inglês do site.

Pré-requisitos e habilidades

Módulos: HTML, CSS e acessibilidade

  • HTML, CSS e acessibilidade
  • JavaScript e DOM
  • Git e GitHub

Inglês do projeto

  • acessibilidade→accessibility (a11y)

    Garantir que pessoas com deficiência consigam usar o site.

  • responsivo→responsive

    Que se adapta a telas de tamanhos diferentes.

  • implantar/publicar→deploy

    Colocar o site no ar.

Como entregar

Crie um repositório público no GitHub para o projeto, com README (o que é, como rodar, como testar, decisões), commits pequenos e frequentes e, a partir do Projeto 2, testes automatizados. Veja o guia de carreira para transformar o projeto em vitrine.
