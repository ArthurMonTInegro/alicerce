Todo processo, menos o primeiro, nasce de outro. Quando você digita python3 app.py no terminal, o shell não se transforma no Python: ele cria um processo filhochild process, faz esse filho trocar de programa e fica esperando ele terminar. O shell é o processo paiparent process. No Unix (Linux, macOS, Android), isso é feito com três chamadas de sistema, os pedidos ao kernel que você viu no nível 0:

  • fork() bifurcafork o processo: a partir dali existem dois, pai e filho, rodando o mesmo código;
  • exec() executa outro programaexec no lugar do atual, dentro do mesmo processo, sem criar processo novo;
  • wait() faz o pai esperarwait um filho terminar e recolher o código de saídaexit status dele.

Separar "criar um processo" de "trocar de programa" parece estranho, mas é o que permite ao shell fazer >, < e |, e é o motivo de cd não poder ser um programa à parte. Essas três chamadas também explicam os processos <defunct> que aparecem no ps de um servidor com bug, o que o subprocess.run do Python faz por baixo e por que, no Linux, processo e thread saem da mesma chamada de sistema.
